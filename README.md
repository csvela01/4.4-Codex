# Actividad de GitHub Classroom: Diseña una Propuesta de Práctica Temática Pequeña

## Descripción general
En esta actividad vas a **diseñar y documentar** una propuesta de práctica temática pequeña que pueda ejecutarse en terminal usando uno de los lenguajes permitidos. El enfoque principal es justificar la idea, delimitar su alcance y dejar una estructura clara de repositorio antes de programar.

## Objetivo de aprendizaje
Al finalizar esta actividad, el estudiante será capaz de:

- Definir un problema concreto y pequeño que pueda resolverse en terminal.
- Justificar técnicamente la elección de lenguaje.
- Organizar un repositorio con estructura clara para GitHub Classroom.
- Documentar caso de uso, alcance y pruebas mínimas.
- Implementar, de forma opcional, un prototipo funcional mínimo.

## Lenguajes permitidos
- ARM64 Assembly
- C
- Python
- Bash

## Reglas para mantener el proyecto pequeño
- Debe resolver **una sola necesidad principal**.
- Debe poder explicarse en 1–2 párrafos.
- Debe requerir pocas entradas y generar pocas salidas.
- Debe ejecutarse localmente en terminal.
- No usar frameworks, bases de datos, nube, Docker ni APIs externas.
- Si eliges ARM64 Assembly, limita la propuesta a programas **muy pequeños**.

## Entregables esperados
1. `docs/propuesta.md` completo.
2. `docs/caso_de_uso.md` completo.
3. `docs/estructura_repositorio.md` revisado y respetado.
4. `docs/plan_de_pruebas.md` completo.
5. `tests/test_plan.md` completo como checklist final.
6. Prototipo mínimo opcional en `src/main.<ext>`.

## Instrucciones para el estudiante
1. Lee este `README.md` y revisa toda la carpeta `docs/`.
2. Elige un tema pequeño (ejemplo: “Asistente de Estudio en Terminal”).
3. Define el lenguaje principal y justifícalo en `docs/propuesta.md`.
4. Documenta un caso de uso realista en `docs/caso_de_uso.md`.
5. Ajusta tu plan de pruebas en `docs/plan_de_pruebas.md`.
6. Completa `tests/test_plan.md` como evidencia rápida.
7. (Opcional) Implementa un prototipo mínimo en `src/`.
8. Asegura que tu entrega sea clara, breve y viable.

## Criterios generales de evaluación
- Claridad del problema y del objetivo de la solución.
- Viabilidad técnica para un proyecto pequeño.
- Coherencia entre alcance, caso de uso y pruebas.
- Organización del repositorio y calidad de documentación.
- Correcta delimitación de lo que **sí** y **no** incluye el proyecto.
- (Opcional) Prototipo mínimo alineado con la propuesta.

## Ejemplos de posibles temas
- “Mini Toolkit en ARM64”
- “Asistente de Estudio en Terminal”
- “Reporteador de Información del Sistema”
- “Organizador de Archivos”
- “Juego de Aprendizaje en Línea de Comandos”

## Nota importante
Primero se documenta y justifica la propuesta. Después, de manera opcional, se implementa un prototipo pequeño. La prioridad de la actividad es la planeación técnica y la comunicación escrita.
